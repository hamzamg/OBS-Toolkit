## 6. What it does

Tuna shows what is playing: track title, artist, album, cover art and progress, pulled from Spotify, Last.fm,
MPD, or Windows media sessions. The output can be a text source, an image source, or a browser-source endpoint
served by the plugin's built-in web server, which is how most overlays consume it.

How it works: a C++ OBS plugin with per-service connectors. It stores service credentials in its configuration
and runs a small HTTP server (cpp-httplib) for overlay clients.

### Installed OBS (system-wide)

The zip uses a `tuna\` root, so the files must be placed explicitly:

1. Back up first, then close OBS.
2. Copy `tuna\tuna.dll` to `C:\Program Files\obs-studio\obs-plugins\64bit\`.
3. Copy the **contents** of `tuna\data\` to `C:\Program Files\obs-studio\data\obs-plugins\tuna\`
   (`lyrics.html`, `widget.html`, `placeholder.png`, `locale\*.ini`).
4. Start OBS.
5. Confirm: **Tools > Tuna** opens the plugin UI, and the log shows the module loaded.

### Portable OBS

Use the same two destinations relative to the portable OBS root.

- The local web server listens on `0.0.0.0` port 1608 by default, with `Access-Control-Allow-Origin: *` and no
  authentication. Anyone who can reach the machine on the network can read the current track and cover image.
- Service API keys, client secrets and tokens are stored in the plugin configuration; treat that folder as a
  secret and never include it in a shared backup.
- Built against OBS 31.1.0; loads on OBS 32 but was not runtime-tested.
